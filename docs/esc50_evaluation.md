# ESC-50 第一轮评测

已有的 `ESC-50-master.zip` 即可使用，不需要解压或下载其他数据集。脚本直接读取其中的 `meta/esc50.csv` 和 WAV，用当前 `configs/windows_sound_events.yaml` 的 YAMNet 权重、目标类别、阈值、0.5 秒步长和连续两窗规则；不会打开麦克风、启动仪表板、上传原音频或修改复核数据库。

在 IDE 终端进入项目根目录 `C:\MMM\cc`，确认 `models/sed/yamnet.onnx` 已存在，再执行：

```powershell
python -m src.pipeline.esc50_eval "C:\Users\user\Downloads\ESC-50-master.zip"
```

预期终端输出 `summary`（正样本正确检出数、负样本出现目标候选数）、`by_category` 和 `report` 路径；完整逐文件检测标签、分数、推理窗口中心时间存入 `reports/esc50_fold1_*.json`，该目录不提交 GitHub。默认取 fold 1 的每类 5 个文件：正样本 `door_wood_knock → Knock`、`clock_alarm → Alarm`、`siren → Siren`，以及键盘、木门吱响、滴答、钟声、车喇叭、玻璃碎、脚步、鼠标、吸尘器和雨声共 10 类负样本。每个 ESC-50 类恰有 40 段、每折 8 段。快速检查可加 `--samples-per-class 1`；跑完整该折用 `--samples-per-class 8`。其余四折可逐次设 `--fold 2` 到 `--fold 5`，不要把同一批结果当独立重复试验。

其中 `clock_alarm` 的 ESC 类别名不保证与 YAMNet 的 `Alarm` 一致；如果出现 `Alarm clock`，但它不在当前目标类白名单中，会按漏检记录。这是现有配置在该素材上的实际表现，不应悄悄改标签来提高数字。ESC-50 没有门铃和普通说话类别，也没有事件起止时刻，故这次只能衡量**剪辑级是否出现目标候选**，不能衡量逐事件召回、报警延迟或真实现场准确率。YAMNet 的 AudioSet 预训练数据可能与 ESC-50 来源重叠；这不是独立的部署效果证明。

先看每个类别的逐文件输出：如果敲门短促而连续两窗规则使检出偏低，再基于同一折比较 `confirm_windows: 1` 和 `2` 对正负样本的影响。下一轮门铃和纯说话对照需要另选素材，带画面的合成片段用于时间轴/证据回看联调，不能代替真实同源音视频测评。

## 2026-10-29 实测基线

使用上述原配置，对五折全部 8 段/类（共 520 段，其中目标声 120 段、指定非目标声 400 段）运行了真实 YAMNet ONNX 推理：目标声正确检出 **49/120**；非目标声出现任一目标候选 **6/400**。逐类：木门敲击 20/40，闹铃 3/40，警笛 26/40。六个非目标候选来自木门吱响 3/40、脚步 2/40、鼠标点击 1/40。这是该固定子集的剪辑级结果，不是全 ESC-50 的误报率，也不能当现场准确率。其他目标标签在正样本上的误分类可在逐文件 JSON 中查看。

特别是 `clock_alarm` 的 3/40 提示：当前白名单里的 `Alarm` 与这类闹铃音色/标签语义可能不一致，且全局第一和两窗确认会进一步限制候选。后续先检查漏检文件的全类别前几名与窗口得分，再考虑另设 `Alarm clock` 类及独立阈值；改设置后必须在留出的文件或另一批数据上复验，不能把同一组数据上的调优结果称为独立测试。
