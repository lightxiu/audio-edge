# 巡检查询试验

本阶段**不需要先录制音视频**。查询只读取本地 `reviews/candidates.sqlite3` 的候选和视频事件；不启动模型检测、不访问麦克风、不改变人工复核结果。没有记录时也会明确显示 0 条。纯音频、纯视频都可单独查询；带音轨的同一文件导入后才会显示 `same_media_file`，仅靠时间接近的事件显示 `temporal_only`。

## 在 IDE 终端体验

1. 在项目根目录运行 `python -m dashboard`，预期终端显示服务运行在 `http://127.0.0.1:8765`。如果 8765 已由音频采集进程占用，就直接使用该进程提供的同一页面，不要再启动第二个服务。
2. 浏览器打开 `http://127.0.0.1:8765`，滚动到“巡检查询”。时间默认为最近一小时，输入问题后按“查询”。预期出现音频和视频记录数、待复核数，以及带事件 ID 的证据列表；若区间内没有记录则显示 0 条，不会虚构事件。时间范围不能超过 24 小时，结束时间不能晚于当前时间。
3. 如果此前已产生音频候选，可点击“回听”；同文件视频证据存在时可点击“看片段”。没有视频片段时不会显示这个链接。视频 HTTP 事件只有元数据，不会自动拥有可播放的画面。
4. 默认尝试本地 `qwen2.5:3b`。若已安装 Ollama，可在另一个终端运行 `ollama serve`（已经运行则无需重复），再确认 `ollama list` 中有 `qwen2.5:3b`；没有则运行 `ollama pull qwen2.5:3b`。查询结果标为“本地模型选取复核重点”。模型离线或输出无效 ID 时，仍返回数据库事实，标为“按时间与待复核状态排序”。第一次离线查询可能需要等待至多约 12 秒。

页面所列事件、时间、复核状态和音视频关系由程序生成，模型仅在**已查到的事件 ID**中选择最多三条重点。查询上限为音频、视频各 50 条；达到上限时请缩小时间范围。`temporal_only` 仅表示前后 5 秒内另有视频事件，不表示同一现场、同一设备或因果关系。模型生成的重点选择不等于准确率、风险判断或人工复核结论。

下一步用一段有使用权限的 30–60 秒带音轨 MP4，标记目标声与非目标声发生的秒数，按 [音视频导入指南](audio_video_event_link.md) 导入，再核对回听、画面片段和巡检查询是否与标注一致。没有真实片段前，不宣称音视频识别效果已经验证。
