# 简历与面试准备稿

这份材料只使用当前 `audio-edge` 仓库已经出现的能力来组织表述。没有在 Jetson 真机上跑出的指标、没有真实模型端到端结果，不应在简历里写成“实测”。

## 项目定位

建议把项目名从“语音助手”收敛为：

**面向 Jetson 边缘设备的实时音频理解与本地 LLM 应用系统**

解决的问题是：在没有稳定外网、数据不方便出内网的场景下，把麦克风音频转成可查询的事件，并提供本地自然语言查询和巡检报告。你的职责应写为“个人完成架构、模块开发、接口联调与测试”，不要把它包装成大模型训练项目。

## 简历项目稿

**面向 Jetson 边缘设备的实时音频理解与本地 LLM 应用系统**  2026.07–至今
Python / ONNX Runtime / TensorRT / Ollama / FastAPI / WebSocket / Docker｜个人项目

- 面向边缘设备离线监测场景，设计“音频采集→环形缓冲区→语音活动检测→关键词/声音事件/场景识别→事件聚合”的实时流水线，并统一 ONNX Runtime / TensorRT 推理接口，支持 Windows 开发与 Jetson 部署切换。
- 独立实现多任务调度、线程间数据传递和事件去重：通过无锁式单生产者/单消费者环形缓冲区承接音频采集，按 KWS、SED、ASC 不同时间窗口调度推理，并用冷却时间/场景滞后抑制重复事件。
- 集成本地 Ollama（Qwen2.5）应用层：将已聚合事件压缩为结构化统计后生成中文巡检报告，设置低温度 Prompt、超时和模板降级；Ollama 不可用时仍输出 Markdown，避免阻塞实时推理链路。
- 使用 LanceDB/向量检索（可选依赖）保存事件，提供 FastAPI + WebSocket 实时仪表板和自然语言查询接口；补充 Mock 输入、模型缺失回退和单元/端到端测试，保证无硬件环境可验证主流程。

如果投递“AI 应用开发”，把第 3、4 条提前；如果投递“边缘部署/视觉部署”，把第 1、2 条提前，并把本项目放在主项目之后。

## 技术栈取舍

优先写能被代码和面试追问支撑的：Python、PyTorch、OpenCV、YOLO、ONNX、TensorRT、Jetson、Docker、FastAPI、WebSocket、Ollama、Prompt 设计、pytest、Git。

LangChain、LangGraph、向量数据库等可以作为“了解/正在补齐”，不要直接放进熟练技能。当前项目的一次性报告调用不需要框架；只有当出现多步工具编排、检索链、结构化输出校验和可观测性需求时，再引入 LangChain/LangGraph 才有解释空间。

## 必须补齐的面试知识

### 1. 本项目主线

- 为什么边缘侧：数据不出内网、无外网依赖、延迟和成本可控。
- 为什么事件先统计再交给 LLM：降低 Prompt 长度和推理开销，把计数、均值、时间范围等确定性工作交给 Python，避免 LLM 算错。
- 为什么需要降级：本地模型可能未启动、模型加载慢或显存不足；报告是附加能力，不能拖垮实时检测主链路。
- 为什么不直接上 LangChain：当前只有一次 Ollama 调用，直接 HTTP 的依赖更少、故障面更小；多步工具调用时再引入框架。

### 2. LLM 应用基础

- Prompt 的系统约束、输入数据和输出格式如何分层；如何通过低温度、事实边界和“暂无证据”减少幻觉。
- Q4 量化是权重精度换显存/速度，可能带来质量损失；与视觉部署中的 FP16 都属于资源和精度之间的工程权衡。
- Ollama 的 `/api/generate` 与 `/api/chat`、同步/流式响应、超时、重试和模型列表接口。
- RAG 的基本链路：切分、向量化、召回、重排、拼接上下文；知道何时需要它，不要把所有问题都做成 RAG。

### 3. Python/部署追问

- 线程适合 I/O 和流水线并发；模型推理是否真正并行取决于底层运行时和 GPU 调度。
- 环形缓冲区为什么避免采集回调阻塞；事件聚合为什么要放在输出前；模型缺失为何回退 Mock。
- ONNX 是交换格式，TensorRT 是 NVIDIA 推理运行时；FP16 通常减少显存和计算开销，但需要验证精度和算子支持。
- Docker 镜像要区分构建平台和运行平台，Jetson 的 ARM64、JetPack、CUDA/TensorRT 版本必须匹配。

## 诚实的指标写法

当前 README 中的 Orin NX 延迟表是目标/预期值，除非你有保存的 benchmark 输出和测试条件，否则简历不要写成实测。可以写“提供 p50/p95/p99 基准脚本”和“设计 ONNX→TensorRT FP16 部署链路”；拿到真机数据后再补具体数字、输入长度、功耗模式和 batch size。
